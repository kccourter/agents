# Workspace Agent Instructions — Example

Adapt this template deliberately to the workspace. Record the actual shared
workflow location, for example `docs/DEVELOPMENT_WORKFLOW.md`, and component
instruction locations. Templates are not active policy until adopted.

## Workflow

- Use local fix/maintenance, cohesive feature, or coordinated-change process
  according to actual scope. Keep one authoritative task/goal index.
- Accept the outcome once; investigate and choose tactics within its invariants,
  ownership, dependency policy, resource ceiling, and external authority.
  Request decisions only for boundaries not already authorized.
- Implementation approval includes the normal local commit after validation and
  review unless the user/project reserves it. Commit completed increments before
  dependent work and report commit/worktree state.
- Preserve unrelated work. Isolate concurrent writers; make index/commit
  ownership explicit and let one coordinator update shared goal status.
- Reconcile required producer commits, contract/fixture identities, and checks
  before consumers proceed. Keep optional work outside the accepted outcome.
- Run relevant required checks; report failed/unexecuted checks as limitations.

## Deliberate local overlays

Replace this section with concrete workspace ownership, runtime and artifact
boundaries, external-action authorization, and required integration gates.
State real constraints and canonical command/doc locations, not a repository
summary. Keep those local overlays out of reusable global skills.
