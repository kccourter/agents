# Pull Request Notes

Use the project's required template when one exists. Scale this example to the
change and omit irrelevant sections.

## Change

Lead with the problem and resulting behavior; include a concrete before/after
example when useful. Identify consequential contracts or design decisions.

## Validation

Commands/results, relevant source/environment/input identities, and any useful
reproduction steps. Distinguish required checks that passed from blockers or
checks that were not run.

## Limits and follow-up

Material remaining risks, unresolved decisions, and separately scoped follow-up.
Include commit/reviewer navigation details only when useful or locally required.
